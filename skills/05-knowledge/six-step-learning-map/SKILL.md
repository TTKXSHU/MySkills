# 六步学习法 / Six-Step Learning Method

用户要学一个新主题时，用**六步法**推进。每一步都有明确的产出和交付标准，不要跳步，也不要一次把六步全倒出来。

```
① 知识地图 → ② 费曼理解 → ③ 最小可跑代码 → ④ 自测纠偏 → ⑤ 工程坑 → ⑥ 刷题巩固
   先走对路     补核心概念     建立直觉          暴露盲区      接上实战     固化留存
```

第 ① 步是入口，用户说"给我 X 的知识地图 / 怎么学 X"时**默认执行第 ① 步**，结尾问是否继续下一步。之后按需推进 ②~⑥，也可以按用户点名的步骤单独执行。

**只有用户明确说"六步全要 / 一次全给 / 全流程"时才一次性输出六步。**

---

## ① 知识地图

**目标**：让用户先看清全貌，再决定从哪切入。**不要一上来就讲细节**。

输出结构（四段，缺一不可）：

**a. 依赖顺序图** —— ASCII 箭头图给出知识块的拓扑依赖，从最底层基础到目标主题。例：

```
数学基础 ──┐
           ├─→ 交流电路/相量 ──→ 三相系统 ──┐
电力电子器件┘                                ├─→ 逆变器拓扑 ──→ PWM 原理 ──→ SPWM ──→ 电机驱动
                                            │
控制基础 ───────────────────────────────────┘
```

**b. 分层知识表** —— 按 L0 / L1 / L2… 分层，每层给：层号、知识块名、具体内容。用表格。

**c. 必须懂 vs 边做边学** —— 三档优先级，每档都要给**理由**：

| 优先级 | 含义 |
|---|---|
| 🔴 必须先懂 | 跳过就判断不了自己做得对不对 |
| 🟡 边做边学 | 做仿真/练习时够用即可，动手后再补 |
| 🟢 后面再说 | 属于目标主题**之上**的层，不是前置 |

**d. 分阶段路线表** —— 每阶段一行：阶段名 / 学什么 / **可验收的产出**。

产出一栏必须是**可验证的动作或实物**（"能算出 X"、"跑通 Y 并画出 Z 波形"、"手动加入 W 并说明原因"），不能是"理解 X"这种无法验收的表述。最后给**建议节奏**（哪几阶段第一阶段完成，哪几阶段属于进阶）。

## ② 费曼理解

**目标**：用类比 + 图示吃下核心概念，**不堆术语**。

做法：
- 先声明用户的假设基础（"假设你懂 PWM 但完全不懂 SPWM"），据此调整深度。
- 每个概念配一个**日常类比**，能画图就画图（ASCII 示意）。
- 讲完立刻**给 2~3 个问题考用户**——这一步不能省，输出才能暴露盲区。
- 用户回答后，先判断对错，再指出**错在哪个环节**。

**禁止**：把教科书段落复述一遍。

---

## ③ 最小可跑代码

**目标**：建立直觉。用户亲眼看到波形，胜过看一百页书。

做法：
- 给**最小可跑**的代码或最小实验（几十行，不是完整工程）。
- 参数（如调制比 m、载波比 N、载波频率）**放在文件开头**，方便用户改。
- 关键行加注释；可视化要能直观对照（如调制波 / 载波 / 输出波**上下对齐子图**）。
- 默认："只要代码，不要额外解释"，除非用户要解释。
- 结尾指出**改哪个参数会看到什么变化**，让用户自己做对照实验。

**优先语言**：用户没说就追问一次（Python 还是 MATLAB/Simulink）。别猜。

---

## ④ 自测纠偏

**目标**：用户输出 → AI 批改 → 用户修正。**理论学习的效率全靠这一步**。

用户说"我跑通了 / 我观察到 XX"时：
1. 先判断他的**理解对不对**（不要先夸）。
2. 不对就精确指出**错在哪一步、为什么错**。
3. 追问这个现象**在工程上叫什么、有什么后果**。
4. 需要时给一个**能自己验证的判别方法**（如改某个参数看波形是否如预期）。

---

## ⑤ 工程坑

**目标**：接上实战。教科书只讲理想波形，**这里才是会烧板子的地方**。

做法：
- 按**严重程度排序**，每条给三要素：**现象 / 原因 / 怎么解决**。
- 覆盖该领域"教科书不讲但会出事"的经典坑。以 SPWM 为例：死区时间、死区补偿、载波频率选型、过调制、母线电压利用率。
- 可配一张表（坑 | 后果）。
- 这一步价值极高，用户到阶段中后期就应主动提示。

---

## ⑥ 刷题巩固

**目标**：固化留存。

做法：
- 给 **5 道难度递增**的题（概念 → 计算 → 调试）。
- **先只给题目，不给答案**；等用户做完再批改，并说明**错误原因**。
- 批改后指出薄弱环节，回到对应步骤补。

---

## 硬性规则

1. **先别讲细节** —— 用户说了这句话就严格执行，第 ① 步整篇不展开任何具体公式的推导。
2. **不要长篇大论** —— 用表格和分点，正文节制。不要给每个概念写一段解释。
3. **阶段产出必须可验收** —— 见第 ① 步。
4. **一次推进一步** —— 除非用户明确要"六步全要"，否则不要一口气把六步全写出来。第 ① 步结尾给"现在就能开始"的钩子，并问一个让工作能继续的具体问题（用什么语言/工具/基础如何）。
5. **诚实的优先级判断** —— 不要把目标主题**之上**的层（如 SPWM 之上的 FOC）列成前置，那会让用户以为必须先学完才能开始。
6. **讲完必有检验** —— 第 ② 步出考题，第 ③ 步让用户改参数，第 ④ 步批改，第 ⑥ 步先题后答。不允许只讲不验。

## 通用提醒

- 所有事实性内容（具体芯片参数、库函数、标准数值）让用户自己复核，不要当成绝对真理。
- **要数字，不要形容词**。拒绝"会影响输出质量"这类模糊说法，追问"影响多少，给个具体数值例子"。
- 用户没给目标/基础/工具时，先追问清楚再展开，不要凭空假设。

## 触发语句示例

- `给我 SPWM 的知识地图` —— 默认执行第 ① 步
- `六步全要，主题是 FOC` —— 一次走完六步
- `从零学 Rust 的学习路线`
- `第二步，给我讲 SPWM 的核心概念` —— 可点名单步
- `SPWM 实际工程里有什么坑` —— 第 ⑤ 步
- `给我 SPWM 练习题` —— 第 ⑥ 步
